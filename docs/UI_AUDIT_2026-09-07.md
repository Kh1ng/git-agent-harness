# UI audit, 7 September 2026

The shared UI has a coherent operator interface. Navigation, status badges,
unknown observations, and retry controls use recognizable product concepts.
The Impeccable detector returned no findings before or after this pass.
Manual inspection found defects that the detector does not cover.

This is a scoped technical review of the web shell, shared tokens, chat
pickers, and desktop connection controls. It is not a WCAG certification or
a claim that every screen and assistive technology has been tested.

## Findings and disposition

Four P1 findings and four P2 findings; no P0 or P3 findings in this scope.

1. **P1: status and secondary text lacked contrast.** `apps/web/src/index.css`
   reused chart colors for small text. Light warning text measured 1.79:1,
   light muted text 3.50:1, and dark critical text 3.62:1 against cards.
   White primary-button text measured 3.64:1. Fixed semantic colors and
   separated the button fill from the link/focus accent. Browser checks now
   require at least 4.5:1 for muted text, buttons, and all four status badges
   in dark, explicit light, and system light themes. Node-setup fields also
   now have the missing shared input style and native controls follow the theme. These fixes address
   WCAG 1.4.3. Suggested command: `$impeccable colorize`.
2. **P1: keyboard focus disappeared.** The shared `.btn` rule and several
   session/chat controls removed outlines without replacement. Removed those
   overrides, added a skip-to-content link, and labeled the session command
   input. Navigation tests check visible focus. This addresses WCAG 2.4.7
   and the repeated navigation bypass in 2.4.1. Suggested command:
   `$impeccable harden`.
3. **P1: modal overlays did not protect keyboard interaction.** Mobile
   navigation, session details, and New Chat used ordinary containers.
   Native dialogs now provide page inertness, Escape dismissal, and focus
   restoration. Navigation also closes on a desktop breakpoint transition.
   This addresses keyboard and modal-dialog semantics. Suggested command:
   `$impeccable harden`.
4. **P1: provider failures looked like empty repositories.** New Chat caught
   issue/PR request failures and displayed an empty list. It now shows the
   failure with a separate Retry action. Selection and request payload tests
   cover recovery. Suggested command: `$impeccable clarify`.
5. **P2: all pages loaded at startup.** `App.tsx` eagerly imported secondary
   pages. React lazy loading and the existing loading state now keep them
   out of the initial bundle. The production build no longer warns about a
   JavaScript chunk over 500 kB. Suggested command: `$impeccable optimize`.
6. **P2: reduced motion used a global near-zero duration.** Replaced it with
   a targeted static alternative for the actual spinning and pulsing status
   indicators. Loading labels remain visible and color transitions remain.
   Suggested command: `$impeccable animate`.
7. **P2: dense controls remain difficult to tap.** Navigation open/close
   buttons are now at least 44 by 44 pixels. Shared buttons and provider
   rows still commonly measure 28–36 pixels high. Review these controls on
   touch devices before mobile release. This is the audit's 44-pixel target,
   not a claim that every smaller target violates WCAG AA. Suggested command:
   `$impeccable adapt`.
8. **P2: some fixed colors bypass semantic tokens.** Chat errors, warnings,
   and issue accents now use theme-aware tokens. Older Settings success
   text and provider favorite stars remain to review in context. Stars are
   an intentional selection cue; their fixed color alone is not evidence of
   a contrast failure. Suggested command: `$impeccable colorize`.

## Verification and limits

- The bundled detector scanned `apps/web/src` and returned `[]` twice. There
  were no detector findings to dismiss as false positives.
- Browser checks cover navigation focus, Escape, backdrop, route selection,
  breakpoint changes, contrast, and named session controls.
- Existing smoke tests passed across five viewport sizes with a hermetic mock
  control plane. They cover seven core routes, not every possible data state.
- Desktop/mobile navigation screenshots and light token samples were inspected.
  Chat picker and desktop settings screenshots were inspected by their agents.
- No new UI dependencies were added. Loading and error components are shared.
- Windows installation, native Dock/tray transitions, iOS, Android, and
  screen-reader testing still require their actual runtime environments.

## Next improvements

Prioritize touch targets and remaining theme classes, then check a packaged
app with VoiceOver and a mobile control client. The next UI pass should use
`$impeccable adapt`, `$impeccable colorize`, then `$impeccable polish` after
those functional checks. Fleet routing, QR pairing, and mobile packaging
remain separate product tickets, not visual polish.
