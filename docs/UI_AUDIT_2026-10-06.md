## Findings and disposition

| ID | Severity | Evidence and impact | Disposition |
| --- | --- | --- | --- |
| A1 | P1 | `ProfileEditor.tsx` DeleteModal used ordinary nested divs. The destructive confirmation had no dialog name/description, initial safe focus, page inertness, Escape dismissal or native focus restoration. Keyboard users could reach the page behind it. | Fixed with the existing native-dialog convention, accessible title/description and initial Cancel focus. Added e2e assertions for naming, focus isolation, Escape, cancellation and restoration. |
| A2 | P1 | All seven ProfileForm labels were adjacent siblings without `htmlFor`/input IDs. Visible field names were not programmatic names, impairing screen-reader configuration and label activation. | Fixed all seven associations with an instance-specific React `useId` prefix, including the disabled edit ID field and provider select. Added accessible-label e2e assertions and field interaction. |
| A3 | P1 | Profile add/save buttons used white small text on `bg-accent`. Dark-theme accent RGB(80,155,245) yields 2.86:1 contrast, below 4.5:1 for normal text. | Fixed both buttons with shared `btn-primary`; fill RGB(30,98,180) yields 6.07:1 against white in both themes. Calculated using WCAG relative luminance; existing Navigation component contrast test covers the shared primary-button style. |
| A4 | P2 | Profile edit/delete icon controls use `p-1.5` around 14px icons (approximately 26px targets); issue-row actions use `p-1` around 13px icons. They bypass shared coarse-pointer minimum sizes. | Remaining touch ergonomics work. No P1 failure inferred solely from a target being below the audit's 44px preference. |
| A5 | P2 | `RepoLinksMenu.tsx` declares menu/menuitem roles while providing ordinary tab navigation and no arrow-key focus handling. | Remaining interaction/semantics consistency work; links remain keyboard reachable through Tab. |
| A6 | P2 | Several Settings errors are plain paragraphs without alert/status semantics, unlike backend availability errors; ProfileEditor success/error notices also lack live announcements. | Remaining asynchronous feedback consistency work. Messages remain visible; no silent failure established. |

Every identified P1 has an implementation fix in this change. No external
follow-up issue was needed for a P0/P1. P2 findings are recorded here for later
triage rather than represented as filed issues.
